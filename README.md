# 命式エンジン

四柱推命の命式を、天文計算から立てる。GitHub Pages で動く静的サイト。

`index.html` を開けば動く。ビルドステップは無い。

## 天盤

画面の中心は、実データで描いた同心円の盤。羅盤の形は借りたが、判断は借りていない。
描いてあるものは全て engine が計算した値である。

- **外環** — 十二節を実際の黄経に置き、立春を天頂に取ってアンラップした環。
  月支の判定に使っている座標そのもの
- **太陽** — 出生時の太陽視黄経
- **内環** — その土地の一日の十二時辰
- **二本の針** — 標準時と真太陽時。**その角度差が27分そのもの**で、
  説明ではなく図形として出る
- **朱の弧** — 誤差棒
- **中心** — 日主

飾りは足していない。逆に、不確かなものを確からしく見せる装飾もしていない。

### 環は読める

環に触れる（またはキーボードでフォーカスする）と、その節の節入り時刻と、
その時辰の時間帯が出る。出るのは全て下の表にもある値で、
**触らないと読めない情報は一つも無い。**

## 読み（Phase 4）

**盤の要素に紐づかない文は、一文も出さない。** 誰にでも当てはまる文を個人向けの
顔で出すことが、このアプリにおける唯一の嘘であり、事実誤りより優先度が高い。

これを気合いではなく構造で守っている。

- 各文は空でない `source` 配列を必ず持つ
- `source` が空の文は **UIで隠すのではなく `readChart` の生成段階で捨てる**
- 出典は画面に出す。読者が全文を盤と突き合わせて検算できる
- 引用された文字が本当に盤にあるかを検算で強制している（架空の引用を防ぐ）

モデルは呼んでいない。全てページ内で計算するので、生年月日も座標も端末から
出ないままで、APIキーも要らない。

蔵干・通変星・十二運は v1 対象外なので、どの規則もそれらに依存していない。
そして**人物についての記述は一切しない** — 書くのは盤の配置についてだけ。

### 反バーナムの計測

```
node tools/reading-metrics.mjs 20000
```

ランダムな命式20,000件で:

| 指標 | 盤の読み | 場面ごとの箇条書き |
|---|---|---|
| 被覆率 | 100.0% | 100.0% |
| 組み合わせ数（異なる読みが何通り作れるか） | 4,301 | 859 |
| 上限到達率（異なる命式 4,342 に対して） | **99.1%** | **19.8%** |
| 最頻共有率 | 0.1% | 1.3% |
| 出典の無い文 | 0 | 0 |

組み合わせを `source` で測るのは、言い換えによる水増しを防ぐため。生テキストで
測ると、同じ主張を書き直しただけで数字が上がってしまう。

**以前ここに書いていた「弁別率 96.1%」は取り下げた。** 定義が
`組み合わせ数 ÷ 標本数` だったので、**標本を増やすと必ず下がる**。同じエンジン・
同じ規則で、標本1,000なら46.2%、4万なら2.4%。あれは品質ではなく標本サイズの
指標だった。いま出しているのは飽和する量——**組み合わせ数**（標本を4万にしても
動かない）と、**上限（異なる命式の数）に対する到達率**。

上の表が示しているのは、盤の読みは上限にほぼ届いているのに、**場面ごとの箇条書きは
19.8%しか出ていない**ということ。箇条書きが見ている材料が
「用神・欠け・判定・通根」の4つしか無いため。

**計測だけで、最適化ループは実装していない。** 正解の無い領域に最適化を掛けると
代理指標は必ず「読んで気持ちいいか」に落ち、自己改善する占い師はバーナム機械に
収束するため。

## 結論を出す — 身強・身弱と用神

四柱推命の鑑定は**判定**に集約される。日主がどれだけ強く立っているか（身強／身弱）、
そこから**その人に必要な五行＝用神**が決まる。ここが無いと、正しい観察が
並ぶだけで何も伝わらない。最初の実装はそれをやっていた。

- 扶抑法。月令を3倍、残る七字を1倍で足し引きし、地支に日主と同じ五行があれば
  通根として +1。±1 の内は中庸
- **点数と内訳を必ず出す。** ラベルだけでなく、境界からどれだけ離れているかも出す。
  近ければ「流派や蔵干の扱いで逆に振れうる」と書く
- 蔵干は入れたが、**流派を選ばず両方計算して割れたら明示する**（下記）
- 重みは定数として並べてある。流派の違いは、その定数を指して議論できる

## 語り（別ページ・voice.html）

**盤のページが自分に禁じているものを、あえて置いた別ページ。** 人物評・助言・
年運がある。

構成は **走り読みできる順序**に従う:
**名前 → 命式 → 目盛り4本 → 強み・つまずき・今すぐ → 場面ごと → 時の流れ → 長文**

### 読めるようにする — MBTI の結果画面から

最初の版は長い文章を9つ縦に積んでいた。「結局なにを言われたのか」を掴むには
全部読むしかない。MBTI の結果画面が分かりやすいのは名前や4文字コードのせいでは
なく、**①軸ごとの％バーで自分の位置が一目で分かる**ことと、**②「強み」「仕事」
などの固定見出しに短い箇条書きが入っていて、知りたいところに直行できる**ことだ。

移したのはその2点だけで、**占いの計算結果は一切変えていない**。4文字コードや
16タイプ名は作っていない——聞かれたのは伝え方であって、名前の付け方ではない。

**目盛り4本**（`app/engine/gauges.js`）。新しい判断は足さず、既に計算済みの値を
位置として見せる。`percent` は常に「左のラベル側へどれだけ寄っているか」で統一し、
色は**寄っている側の端から**塗る。左から塗ると、身弱の盤で「力が余る」側に色が
伸びて、絵と文字が逆のことを言う。

| 目盛り | 左 ↔ 右 | ％の定義 | 実測（2万件） |
|---|---|---|---|
| 出し方 | 外に出す ↔ 内にためる | 8文字のうち陽の割合 | 中央値 50%、4対4 が 40% |
| 力の余り | 力が余る ↔ 削られる | 扶抑法のスコア（±8でクランプ、中庸帯を帯で描く） | 5〜95%分位 −4.9〜+5.0 |
| かたより | 一点集中 ↔ まんべんなく | 最多五行 ÷ 8 | 4つ以上=30.3%、3つ=54.8% |
| 土台 | 土台がある ↔ 身軽 | 通根した地支 ÷ 4（蔵干込み） | 0本10% 1本29% 2本31% 3本22% 4本8% |

**流派で反転する目盛りには、その盤で印を出す。** 蔵干を数えるかどうかで
「力の余り」は **15.1%** の盤が左右反転し、「土台」は **28.4%** が反転する
（実測）。時刻の誤差棒が日柱をまたぐときは、日主に載っている2本が暫定であることも
出す。§2.5 が時刻にしている扱いと同じで、片方の流派の答えを唯一の答えとして
出さない。

**場面ごとの箇条書き**（`app/engine/domains.js`）。エンジンの結論は
「削られる側、金に寄れ」——正しくて出典もあるが、転職を迷っている人には使えない。
**用神・欠け・判定・通根**の4つを、仕事／人づきあい・恋愛／お金／心と体に
投影する。新しい占い規則は作っていない。1セクション3件まで、優先順位で決定論的に
選ぶ（乱数もローテーションも使わない）。

**長い文章は消していない。** 各セクションの「もっと読む」の中に畳んだだけで、
`plainwords.js` の言い回しはそのまま生きている。

### 型に名前を付ける

天星術が機能するのは、読み手が「私は満月」と言って帰れるからだ。四柱推命は
素材をすでに持っている——**十干の象**（甲＝大樹、辛＝珠玉、壬＝大海…）と
**月支の季節**。掛け合わせると40通りの型名になり、全て盤から導出される。

> 夏の珠玉 ／ 冬の大樹 ／ 秋の灯火

### 言葉を今の日本語にする

最初の版は文体が古かった。「無理が利かないのではなく、無理の利かせ方が違う」
——かっこつけているだけで伝わらない。専門語も画面に出しっぱなしだった。
四柱推命の本を一度も開いたことがない人には、何を言われているのか分からない。

全ての表示テキストを `app/engine/plainwords.js` に集約し、一つの規則で書き直した。
**友達に説明するように書く。**

- 二人称、です・ます、短い文
- 専門語は先に出さない。小さく後ろに添えるだけ
- 抽象を必ず具体に着地させる。「所属」ではなく「会社でも家でも、続けている習慣でもいい」
- 体言止め・文語・箴言を使わない

| 元 | 今 |
|---|---|
| 日主 | あなたの本体 |
| 身弱 | エネルギー控えめ型 |
| 用神 | 効くこと |
| 相生／相剋 | 助ける／削る |
| およそ42件に1件 | 42人に1人 |

### 「統計に基づく」を実際にやる

この種の占いは「統計学に基づく」と謳うが、数字はまず出てこない。
こちらは出す。**型名を含む全ての一節に、20,000件の実測頻度が付く**。
「およそ42件に1件」——当たっていると感じたとき、それが何人に当たる文なのかが
その場で分かる。

分けたことが正直さの本体である。盤のページでは全文が八字と突き合わせて検算でき、
出典の無い文は生成段階で捨てられる。語りのページは語り口が変わり、
**そのことをページ自身が冒頭で言う**。同じ重さで受け取られないために。

それでもバーナム機械にしないための縛り:

- 全ての一節が特定の文字に紐づき、出典を持つ（誰にでも当てはまる文にならない）
- 十干の象（甲＝大樹、辛＝珠玉、壬＝大海…）は伝統の受け売りで、当方の創作ではない
- **各節に「およそN件に1件」を付ける。** 当たっていると感じたとき、その配置が
  3件に1件なら、同じ文は世の中の3分の1に当たっている
- 同じ検算を語りにも掛けている（出典の有無・引用文字が盤にあるか・珍しさの実測値があるか）

**実測がバーナム文を1件捕まえた。** 「土台があるので、続けたものが実力として
残ります」は 通根の有無（あり／なし）に載せていたが、通根は **89.7%** の盤で
「あり」になる。ほぼ全員に当たる文をお世辞として出していたわけで、
`tools/reading-metrics.mjs` がそれを 70% 超として弾き出した。同じ事実を
**本数**（0〜4本、10/29/31/22/8%）に載せ替えて解決した。境目は2本で、
盤を 61% / 39% に割る。

年運は立春で切り替える。1月1日ではない。

## 時の欄 — 同じ問いを4つの倍率で

10年（大運）／今年／今月／今日を1本の列に並べる。問いはどれも同じ——
**巡ってきているのは、この盤が必要とする五行か、消耗する五行か。**

並べることが本体である。**追い風の10年の中の悪い日**と、**向かい風の10年の中の
悪い日**は別の事実で、並べないと自分がどちらにいるか分からない。

> 今日は木の日で、あなたには**向かい風**です。
> ただ、上の段もそろって向かい風です。今日だけの問題ではないので、
> 今日の不調を今日のせいにしないほうがいいです。長い向かい風の中の一日です。

「今」の四柱も命式と同じ engine で立てる。年は立春で、月は節入りで切り替わる。
**日運を暦の月日で計算したら、年に十数回、自分の命式と矛盾する。**

## 蔵干 — 支の中に隠れている干

地支は一つの五行ではない。寅は名目上は木だが、甲（本気）・丙（中気）・戊（余気）を
抱えている。名目の五行だけ数えるのは、そこにあるものの一部しか数えていない。

**流派を一つ選んで黙って使うのではなく、両方計算して割れたら言う。**
仕様§4が定気/恒気に与えているのと同じ扱いにした。

### 表を構造で検算する

手で書いた表なので、信じずに**2つの構造規則から再導出して照合**している。

- **余気＝前の支の本気**。丑は子を受けて癸、卯は寅を受けて甲、午は巳を受けて丙。
  例外なく12支すべて（亥→子で一周する）
- **中気＝三合局の相手**。寅午戌は火に集まるので寅は丙、戌は丁。申子辰は水、
  亥卯未は木、巳酉丑は金。四正のうち子卯酉には中気が無い（午だけは己を持つ例外）

**この検算が実際に誤りを捕まえた。** 戌の中気と余気を入れ替えて書いていた
（正しくは 中気丁・余気辛）。表のtypoは黙って全ての判定を曲げるので、
構造から照合していなければ気づけなかった。

各支の重みは合計1に正規化してあるので、蔵干を入れても点数のスケールが変わらず、
2つの計算を直接比べられる。

## 大運 — 「いつ」が言えるようになる

ここまでは固定した盤の話だった。大運は、それを時間軸に載せる。
**必要な五行が実際にどの10年で巡ってくるか**、どの10年が逆風か。
四柱推命が判断に使われる理由の中心はここにある。

- **向き**: 陽男陰女は順行、陰男陽女は逆行。これが性別を要求する唯一の理由で、
  そう明記したうえで「答えない」も選べる（選ばなければ大運だけ出ない）
- **立運**: 順行なら生まれてから次の節入りまで、逆行なら前の節入りから生まれた時まで。
  その日数を3で割る（3日＝1年、余り1日＝4ヶ月）。**元の日数も画面に出す** —
  流派が争っているのはその丸め方だから
- 節入りの瞬間は月柱と同じ engine から取るので、§2の27分は既に入っている

出力は10年ごとの帯で、各期が追い風か向かい風かを色で示し、現在地を印す。

> いまは27〜37歳の乙酉。向かい風の10年です。
> 次に追い風の10年が来るのは**57歳から**（戊子・土）。21年先です。

## 名前も見る（姓名判断）

四柱推命と姓名判断は別の体系なので、混ぜて一つの結論にはしない。
ただし**両方とも五行を語る**——ここが唯一、正当につながる場所である。

命式はすでに「その人に効く五行（用神）」を出している。だから名前に聞ける問いは
一つに絞れる: **あなたの名前は、命式が足りないものを補っているか？**

### 画数の出典

**KANJIDIC2**（EDRDG, CC BY-SA 4.0）の `<stroke_count>`。日本の漢字辞典の数え方。

Unihan の `kTotalStrokes` は使わなかった。中国字形に従うため、辶 と 阝 を含む字で
日本の慣行とずれる。**郎 を8画とする**（辞典は9画）——日本人の名前で最頻の字の一つで、
ここを外すのは致命的だった。既知19字で照合して Unihan 19/21、KANJIDIC2 21/21。

濁点・半濁点は NFD 分解して +2 / +1。画数が引けない文字は0扱いにせず、
「読めなかった字」として画面に出す。

### 入れなかったもの

**81画の吉凶表**。市販の姓名判断の中心だが、流派差が大きく、黙って載せると
流派を一つ選んで隠すことになる。実測できる根拠も無い。入れるなら、天体暦や
万年暦と同じように出典を名指しして入れる。

## 仕様からの逸脱（作者承認済み）

v2仕様 §5 は「参照するのは占いアプリではなく紙の万年暦」「動きは27分トグルに
だけ使う」と定めている。見た目を占いらしく強くする方針に切り替えたため、
以下を意図的に上書きしている。**盤の計算内容は一切変えていない。**

| 仕様 | 現状 | 理由 |
|---|---|---|
| 万年暦の緊張感を素材にする | 羅盤＋星空 | 見た目の方針変更。判断は借りていない |
| 動きは27分トグルにだけ | 針の掃引・登場・星の瞬き | 同上。`prefers-reduced-motion` は全て尊重 |
| 五行五色をそのまま使う | 実測で再ステップ | 元の色は暗い地色上で判別不能だった（下記） |
| §8「人物評を出さない」 | 盤のページでは厳守。語りは別ページに分離 | 作者の依頼。混ぜず、確からしさの違いを明示した |

一方、次の骨は仕様どおり残している。朱は節入り時刻専用。五色は大面積に
使わない。誤差棒の3状態。分岐軸を隠さない。出典の無い記述を書かない。

### 五行の色を実測で作り直した理由

仕様の五色をマーク色に使うと、計測上こうなる:

- 木 `#2E5E4E` と 火 `#A8322D` が protanopia で **ΔE 5.6** しか離れない
- 水 `#1C2430` は地色そのもので **コントラスト 1.12** — 不可視

五行の読みは保ったまま再ステップし、CVD分離 8.6 / 通常視 16.0 /
全スロット 3:1 以上を通した。金が無彩色寄りなのは金の意味そのもので、
識別は常に隣の干支文字が担っている。

## 立っているもの

- **真太陽時**を実際に計算する。地方時差（岩見沢で +27分）と均時差（最大 ±16分）を、
  Swiss Ephemeris の `swe_time_equ` から取る。近似式は書いていない
- **節入りは UT で判定する。** 年柱・月柱に地方時差を掛けない。掛けると27分ぶん狂う
- **誤差棒を持つ。** 出生時刻の確からしさを入力し、境界をまたぐときは両方の命式を並べる
- **流派で割れる軸を隠さない。** 12通りを内部で全て計算し、実際に分岐する軸だけを開く
- **外部に何も送らない。** 天体暦は同梱。読み込み後の通信はゼロ。保存もしない

## 動かす

静的ファイルなので、HTTP で配れば動く。`file://` では WebAssembly を読めない。

```
python3 -m http.server 8000
```

## 精査で見つけて直したもの

MBTI 式の伝え方を入れたあと、穴とバグを探して10件見つけた。実測で裏を取ったものだけ
書く。重かったのは「もっともらしく見えて中身が無い」種類。

**画数が1文字も引けない名前に、断定を返していた。** `Smith / John` を入れると五格が
すべて 0画 になり、`elementOfCount(0)` がそれを素直に「水」と読んで、
「名前は足りないものを補う側には回っていない」と言い切っていた。出典チップには
`人格:0画` `element:水` と出るので、**形式上は出典付きに見えて中身が空**——出典チップ
機構が防ぐはずだった失敗そのもの。いまは姓か名の既知文字が0なら節ごと出さない。
人格は姓の末字と名の頭字の2文字だけで決まるので、その2文字が引けないときも出さない。

**時の欄が自分と矛盾していた。** 「今日は**向かい風**です。特に押しも引きもない日です。」
今日が向かい風で上の段が同数のとき、分岐が抜けて中庸用の文に落ちていた。3,000命式で
1.0%。いまは54通りの組み合わせを全部掃いて検算している。

**`speak()` の中に「いま」が2つあった。** 年運は引数の `nowJdUt` を見て、時の欄は
`new Date()` を見ていた。2030年を渡すと年運だけ動いて今日の行は動かない。これは
2文が食い違うだけでは済まず、**`today:*` の頻度が生成した日の実時計に依存する**ため、
「20,000人ぶんを実際に数えた」がそのキーについて再現できなくなっていた。いまは一つの
「いま」が全体を動かし、頻度表には**数えた日付が刻印される**（`RARITY_COUNTED_ON`）。
`node tools/build-rarity.mjs 20000 2026-07-30` で再現できる。

**出典チップと注意書きが WCAG AA 未達だった。** `--ink-faint` #626C7C は背景の上で
3.69:1、オーロラの上で **3.23:1**（10〜11.5px の文字に必要なのは 4.5:1）。使用箇所26、
その中に `.cite`（**出典チップ全部**）と `.hint`（**注意書き全部**）。いちばん読みにくい
文字がいちばん正直さを担っているのは逆立ちしている。色相を保ったまま #7A869A に上げて
5.32:1 / 4.65:1。コントラストは `verify.mjs` が CSS から読んで計算で検算する。

**盤ページと語りページが違う命式を出しうる。** 盤の真太陽時トグルを切ると、4,000命式で
**40.9%** が別の命式になり、**8.5%** が別の判定、**11.7%** が別の用神になる。どちらの
ページもそれを言っていなかった。いまは補正を切ると盤のフッターに注意が出て、語りページは
「真太陽時で読んでいます」と明示する。

**未来の生年月日を受け付けていた。** 1929を2029と打つと年齢が −5歳 になり、大運の行が
黙って消えて、残りは普通に描画されるので**壊れていることが画面から分からない**。いまは
`max` を今日に切り下げ、その裏で JS も弾く（`max` を外しても弾けることを検算している）。

**使っていない緯度を必須で訊いていた。** 真太陽時のずれは経度だけで決まるので、緯度は
命式に一切効かない。保存も送信もしないアプリに「記録として受け取る」入力欄が要る理由は
無い。外した。

ほかに、JS の例外文がそのまま日本語UIに出ていたのを日本語の文に（詳細はコンソールへ）、
`cycleAtAge` が壊れた引数で落ちるのを null 返しに、弁別率の指標そのものを差し替えた
（上の「反バーナムの計測」）。

**探して問題が無かったもの**も書いておく: HTML注入の経路（`el()` は `textContent`、
`innerHTML` の1箇所は補間なしの静的文字列）、蔵干の配分合計（全12支で1.000）、
1800年と2399年の両端、閏日、1948〜51年の夏時刻、時刻不明の三柱、経度や時刻が NaN の
とき、名前の前後空白・濁点・サロゲートペア・かな。

## 検算

```
node tools/verify.mjs              # 81項目。VERIFY.md を生成する
node tools/reading-metrics.mjs     # 組み合わせ数・上限到達率、バーナム文の検出
node tools/build-rarity.mjs 20000 2026-07-30   # 各文の出現頻度を測り rarity.js を生成
```

国立天文台の公表値・Meeus の既知例・独立した2つの万年暦と突き合わせ、
一つでも合わなければ非ゼロで終了する。

伝え方の層にも同じ門を掛けている（2,000命式を掃いて検算）:

- 目盛り4本が 0〜100 に収まる
- **力の目盛りが身強身弱の判定と必ず同じ側を指す**（絵と結論が食い違わない）
- 蔵干で判定が割れる盤では目盛りに警告が出る
- 目盛りも箇条書きも、出典が空なら生成されない
- 4場面はどれも空にならず、3件を超えない
- 全ての箇条書きキーが頻度表に載っている（「◯人に1人」が黙って消えない）
- 同じ生年月日は毎回同じ箇条書きを出す（乱数を入れていないことの検算）
- **時刻不明の三柱でも例外を投げない**——これは実際に落ちていた回帰テスト

ブラウザ側の不変条件は別に測る（375px と 320px、`prefers-reduced-motion` 含む）:
初回ロード後の通信0件・ストレージ0件・横あふれなし・ページエラーなし。

## v1 の対象外

意図的に実装していない。無言で落とすと事故になるので明記する。

- 流年（年運は語りページに簡易版あり）
- 通変星・十二運
- 都市名検索（ジオコーディング通信が出るため。緯度経度の手入力のみ）
