# 命式エンジン

四柱推命の命式を、天文計算から立てる。GitHub Pages で動く静的サイト。

`index.html` を開けば動く。ビルドステップは無い。

## 天盤

画面の中心は、実データで描いた同心円の盤。羅盤の形は借りたが、判断は借りていない。
描いてあるものは全て engine が計算した値である。

- **外環** — 十二節を実際の黄経に置き、立春を天頂に取ってアンラップした環。
  月支の判定に使っている座標そのもの
- **太陽** — 出生時の太陽視黄経
- **内環** — その土地の一日の十二時辰
- **二本の針** — 標準時と真太陽時。**その角度差が27分そのもの**で、
  説明ではなく図形として出る
- **朱の弧** — 誤差棒
- **中心** — 日主

飾りは足していない。逆に、不確かなものを確からしく見せる装飾もしていない。

### 環は読める

環に触れる（またはキーボードでフォーカスする）と、その節の節入り時刻と、
その時辰の時間帯が出る。出るのは全て下の表にもある値で、
**触らないと読めない情報は一つも無い。**

## 読み（Phase 4）

**盤の要素に紐づかない文は、一文も出さない。** 誰にでも当てはまる文を個人向けの
顔で出すことが、このアプリにおける唯一の嘘であり、事実誤りより優先度が高い。

これを気合いではなく構造で守っている。

- 各文は空でない `source` 配列を必ず持つ
- `source` が空の文は **UIで隠すのではなく `readChart` の生成段階で捨てる**
- 出典は画面に出す。読者が全文を盤と突き合わせて検算できる
- 引用された文字が本当に盤にあるかを検算で強制している（架空の引用を防ぐ）

モデルは呼んでいない。全てページ内で計算するので、生年月日も座標も端末から
出ないままで、APIキーも要らない。

蔵干・通変星・十二運は v1 対象外なので、どの規則もそれらに依存していない。
そして**人物についての記述は一切しない** — 書くのは盤の配置についてだけ。

### 反バーナムの計測

```
node tools/reading-metrics.mjs 1000
```

ランダムな命式1,000件で:

| 指標 | 値 |
|---|---|
| 被覆率 | 100.0% |
| 弁別率（生テキストではなく `source` の組み合わせで測る） | 96.1% |
| 被覆率 × 弁別率 | **96.1%** |
| 出典の無い文 | 0 |
| 最も多い読みを共有する命式 | 1000件中4件（0.4%） |

弁別率を `source` で測るのは、言い換えによる水増しを防ぐため。生テキストで
測ると、同じ主張を書き直しただけで数字が上がってしまう。

**計測だけで、最適化ループは実装していない。** 正解の無い領域に最適化を掛けると
代理指標は必ず「読んで気持ちいいか」に落ち、自己改善する占い師はバーナム機械に
収束するため。

## 語り（別ページ・voice.html）

**盤のページが自分に禁じているものを、あえて置いた別ページ。** 人物評・助言・
年運がある。

分けたことが正直さの本体である。盤のページでは全文が八字と突き合わせて検算でき、
出典の無い文は生成段階で捨てられる。語りのページは語り口が変わり、
**そのことをページ自身が冒頭で言う**。同じ重さで受け取られないために。

それでもバーナム機械にしないための縛り:

- 全ての一節が特定の文字に紐づき、出典を持つ（誰にでも当てはまる文にならない）
- 十干の象（甲＝大樹、辛＝珠玉、壬＝大海…）は伝統の受け売りで、当方の創作ではない
- **各節に「およそN件に1件」を付ける。** 当たっていると感じたとき、その配置が
  3件に1件なら、同じ文は世の中の3分の1に当たっている
- 同じ検算を語りにも掛けている（出典の有無・引用文字が盤にあるか・珍しさの実測値があるか）

年運は立春で切り替える。1月1日ではない。

## 仕様からの逸脱（作者承認済み）

v2仕様 §5 は「参照するのは占いアプリではなく紙の万年暦」「動きは27分トグルに
だけ使う」と定めている。見た目を占いらしく強くする方針に切り替えたため、
以下を意図的に上書きしている。**盤の計算内容は一切変えていない。**

| 仕様 | 現状 | 理由 |
|---|---|---|
| 万年暦の緊張感を素材にする | 羅盤＋星空 | 見た目の方針変更。判断は借りていない |
| 動きは27分トグルにだけ | 針の掃引・登場・星の瞬き | 同上。`prefers-reduced-motion` は全て尊重 |
| 五行五色をそのまま使う | 実測で再ステップ | 元の色は暗い地色上で判別不能だった（下記） |
| §8「人物評を出さない」 | 盤のページでは厳守。語りは別ページに分離 | 作者の依頼。混ぜず、確からしさの違いを明示した |

一方、次の骨は仕様どおり残している。朱は節入り時刻専用。五色は大面積に
使わない。誤差棒の3状態。分岐軸を隠さない。出典の無い記述を書かない。

### 五行の色を実測で作り直した理由

仕様の五色をマーク色に使うと、計測上こうなる:

- 木 `#2E5E4E` と 火 `#A8322D` が protanopia で **ΔE 5.6** しか離れない
- 水 `#1C2430` は地色そのもので **コントラスト 1.12** — 不可視

五行の読みは保ったまま再ステップし、CVD分離 8.6 / 通常視 16.0 /
全スロット 3:1 以上を通した。金が無彩色寄りなのは金の意味そのもので、
識別は常に隣の干支文字が担っている。

## 立っているもの

- **真太陽時**を実際に計算する。地方時差（岩見沢で +27分）と均時差（最大 ±16分）を、
  Swiss Ephemeris の `swe_time_equ` から取る。近似式は書いていない
- **節入りは UT で判定する。** 年柱・月柱に地方時差を掛けない。掛けると27分ぶん狂う
- **誤差棒を持つ。** 出生時刻の確からしさを入力し、境界をまたぐときは両方の命式を並べる
- **流派で割れる軸を隠さない。** 12通りを内部で全て計算し、実際に分岐する軸だけを開く
- **外部に何も送らない。** 天体暦は同梱。読み込み後の通信はゼロ。保存もしない

## 動かす

静的ファイルなので、HTTP で配れば動く。`file://` では WebAssembly を読めない。

```
python3 -m http.server 8000
```

## 検算

```
node tools/verify.mjs              # 40項目。VERIFY.md を生成する
node tools/reading-metrics.mjs     # 被覆率 × 弁別率
node tools/build-rarity.mjs        # 各文の出現頻度を測り rarity.js を生成
```

国立天文台の公表値・Meeus の既知例・独立した2つの万年暦と突き合わせ、
一つでも合わなければ非ゼロで終了する。

## v1 の対象外

意図的に実装していない。無言で落とすと事故になるので明記する。

- 蔵干（流派分岐が大きい）
- 大運・流年
- 通変星・十二運
- 都市名検索（ジオコーディング通信が出るため。緯度経度の手入力のみ）

## 構成

```
index.html          盤
voice.html          語り
app/
  engine/
    swe.js          Swiss Ephemeris の束縛。UT系のみを公開する
    time.js         時刻の正規化。t_ut と t_true を別々に持つ
    terms.js        節入り。立春を起点に黄経をアンラップする
    pillars.js      四柱。五虎遁・五鼠遁は明示テーブル
    chart.js        12通りの算出と、軸ごとの差分判定
    uncertainty.js  誤差棒。確定／境界近傍／不明の3状態
    reading.js      読み。全文が出典を持ち、無い文は生成段階で捨てる
    voice.js        語り（別ページ）。人物評・助言・年運
    rarity.js       各文の出現頻度（生成物）
  voice-main.js
  ui/
    dial.js         天盤（SVG）
    sky.js          星空（Canvas、手続き生成・画像なし）
    render.js
  main.js
  style.css
vendor/swisseph-wasm/   同梱の天体暦（GPL）
tools/
  verify.mjs           検算（40項目）
  reading-metrics.mjs  被覆率 × 弁別率
  build-rarity.mjs     出現頻度の実測
VERIFY.md
```
